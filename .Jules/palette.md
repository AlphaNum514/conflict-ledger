## 2026-11-04 - Keyboard-Accessible Glossary Accordions
**Learning:** When retrofitting existing custom accordions (like the Technical Glossary here) with keyboard accessibility, adding `tabindex` and an `onkeydown` handler is not enough. Screen readers also need correct ARIA bindings (`aria-expanded`, and crucially `aria-controls`) explicitly linking the trigger to the content block. And since the toggling was handled by JS manipulating `max-height`, the `aria-expanded` attribute must dynamically update in the JS function to reflect the real state.
**Action:** Always ensure that when adding `id`s to disclosure content for accessibility, `aria-controls` is added to the corresponding triggers. Also, if there's custom JS toggling the display, update the JS to toggle the `aria-expanded` attribute dynamically.
