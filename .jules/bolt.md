## 2026-06-25 - Layout Thrashing in Scroll Listeners
**Learning:** Accessing `offsetTop` or `scrollHeight` inside high-frequency scroll events without throttling causes "layout thrashing" because the browser must synchronously recalculate the layout before returning the value. In single-page apps with many sections, this significantly impacts scroll performance.
**Action:** Always cache layout-sensitive values (like section offsets) in a variable and only update them when the layout actually changes (resize, view switch, content expansion). Use `requestAnimationFrame` to batch any DOM writes (like updating progress bars or classes) to ensure they happen at the start of the next frame.

## 2026-07-16 - Eliminating Tooltip Tracking Lag via GPU Layer Promotion & Dimension Caching
**Learning:** Mouse movement triggers mousemove events at very high frequencies (up to 240Hz+). Updating layout-inducing properties like `left` and `top` inside this hot path, while simultaneously querying layout properties like `tip.offsetHeight`, causes immediate layout thrashing and dropped frames. By utilizing GPU layer promotion (`will-change: transform` and `position: fixed`) and translating the tooltip via `translate3d()`, the browser can bypass the expensive layout and paint phases entirely, relying solely on rapid GPU compositing.
**Action:** When tracking cursor position for tooltips or floats, cache the element dimensions once when showing, pre-apply responsive constraints before measurement, and position via GPU-accelerated 3D transforms inside a `requestAnimationFrame` throttle.
