## 2026-06-25 - Layout Thrashing in Scroll Listeners
**Learning:** Accessing `offsetTop` or `scrollHeight` inside high-frequency scroll events without throttling causes "layout thrashing" because the browser must synchronously recalculate the layout before returning the value. In single-page apps with many sections, this significantly impacts scroll performance.
**Action:** Always cache layout-sensitive values (like section offsets) in a variable and only update them when the layout actually changes (resize, view switch, content expansion). Use `requestAnimationFrame` to batch any DOM writes (like updating progress bars or classes) to ensure they happen at the start of the next frame.

## 2026-07-21 - Responsive Layout Caching and Event Object Recycling in RAF
**Learning:** In high-frequency event listeners like `mousemove` that are throttled via `requestAnimationFrame`, accessing event properties (such as `clientX`/`clientY`) inside the async RAF callback can lead to coordinate errors or exceptions because browsers recycle event objects. Additionally, caching tooltip dimensions (`offsetWidth`/`offsetHeight`) requires applying responsive width CSS constraints (`maxWidth`) *before* measuring, to ensure measurements reflect the final reflowed viewport boundaries.
**Action:** Always copy high-frequency event properties to local/scoped tracking variables synchronously before entering the RAF callback. For dynamic elements, apply any responsive viewport-relative style constraints before reading layout dimensions for caching.
